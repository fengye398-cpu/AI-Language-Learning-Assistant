一、软件简介

AI 语言学习助手是一款基于大语言模型的桌面学习工具，专为语言学习者设计。通过调用兼容 OpenAI 接口的 API（如 DeepSeek），可帮助您完成翻译、音标查询、词义解释、例句生成、格式化的语言分析等语言学习任务。

二、安装与启动

2.1 环境要求

  • Python 3.8 或更高版本
  • 依赖库：openai、tkinter（Python 自带）

2.2 安装依赖

pip install openai

💡 若使用打包后的可执行文件（.exe），可跳过此步骤。

2.3 启动程序

方式一：源码运行

python WINAPI.py

方式二：双击运行

若已通过 PyInstaller 打包，直接双击生成的 .exe 文件即可。

2.4 首次启动

首次运行时程序会自动创建以下文件（与程序同目录）：

文件名说明
config.json保存 API 配置、窗口位置、置顶状态等
prompts.json保存提示词列表及勾选状态
send_log.txt发送日志，记录每轮实际发送内容（自动生成）

⚠️ 首次启动必须先配置 API Key，否则无法发送消息。

轮数标签含义

工具栏最右侧显示当前上下文轮数，例如 3 / 8 轮：

  • 左边数字：history 里已攒的轮数。
  • 右边数字：设置里的「上下文轮数」上限。
  • 超过上限后会显示如 9 / 8，但发送时始终只取最近 8 轮，更早的会被自动挤掉。
  • 点【清空】会把轮数重置为 0。

3.2 输入框

  • 支持撤销（Ctrl+Z）
  • 快捷键 Ctrl+Enter 快速发送（带规则）

3.3 对话区

  • 【AI】：黑色，显示 AI 的回复（流式逐字显示）
  • 系统消息：灰色斜体，显示错误提示、规则附加提示等

3.4 状态栏

4.3 上下文轮数详解

含义：每次发送时，除本次内容外，还携带最近 N 轮历史对话。

计算：1 轮 = 1 次用户提问 + 1 次 AI 回复。

重要：规则勾选与上下文轮数的关系

勾选的规则不会存入历史。历史里只保存你输入的原始内容。

每轮发送时，程序会把勾选的规则重新拼接到当前这条消息里，所以：

  • 规则每轮都在最新位置出现，优先级最高，不依赖历史记忆。
  • 即使上下文轮数设为 0，规则依然生效。
  • 历史只占用“原始对话”的空间，不会被规则重复占满。

重要：轮数达到上限会怎样

  • 工具栏显示如 8 / 8 轮，表示 history 里已攒了 8 轮。
  • 达到上限不会阻止发送，继续发送会显示 9 / 8、10 / 8。
  • 发送时始终只取最近 N 轮，旧的会自动被挤掉。
  • 显示超过上限只是提示，不影响功能。

建议值：

轮数适用场景说明
0每轮独立句子、规则固定（推荐）不携带历史，每轮完全独立。省 token，格式最稳。
1~2偶尔追问上一句仅保留极少量上下文。
4~8连续讨论、追问、指代需要模型记住前面聊过什么时才用。
>16不推荐token 消耗大，响应慢，格式漂移风险高。

限制：必须为非负整数（0 也允许），否则保存时会提示。

💡 如果你每轮都是“勾选规则 + 一句新句子”，建议把轮数设为 0。

此时历史对话对当前轮没有帮助，反而可能：

  • 浪费 token，增加费用
  • 把上一轮的错误格式带进来
  • 把上一句内容混进这一句

设 0 后，每轮只发「规则 + 当前句子」，最干净、最省、最稳。

五、提示词与规则勾选

点击工具栏 【提示词】 按钮打开管理窗口。这是本软件的核心功能之一。

5.1 提示词的作用

  • 快捷填入：把高频提示语一键填进输入框。
  • 规则勾选：勾选后，每次发送时自动把规则拼在句子前面，彻底解决多轮对话格式漂移问题。

5.2 窗口结构

┌─────────────────────────────────────────┐ │ ☑ 提示词 │ ← 复选框列 + 内容列 │ ☐ 请把下面的内容翻译成英语... │ │ ☑ 请按以下格式输出日语注音... │ │ ☐ 请解释下面这段话的语法结构... │ │ │ ├─────────────────────────────────────────┤ │ [全屏] [新增] [删除] [关闭] │ └─────────────────────────────────────────┘

5.3 复选框勾选机制（重点）

提示词列表每行最左侧有一个复选框，用字符显示：

  • ☐：未勾选，该条不会自动附加
  • ☑：已勾选，每次发送时自动附加到当前消息前面

勾选方式

操作效果
单击复选框列切换该行勾选状态，立即保存，并选中该行
选中多行后按空格批量切换所有选中行的勾选状态
Ctrl+A全选所有行
Ctrl / Shift + 单击多选行（不改变勾选）

多项勾选规则

  • 允许多条同时勾选，默认不勾选任何规则。
  • 勾选多条时，发送时会按列表顺序依次拼接，每条之间空一行。
  • 勾选状态自动保存到 prompts.json，下次打开程序仍然记得。

发送时的拼接格式

假设你勾选了 2 条规则，输入框写了一句日文，实际发送内容为：

规则1正文

规则2正文

【要处理的内容】
ジョージは寝かしつけるのが大好き

对话区只显示你输入的原始句子，并附一行灰色提示：[已附加 2 条规则]。

两种“不带规则发送”的方式

方式一：取消勾选所有规则，点【发送】

  • 适合整段时间都不需要规则。
  • 缺点：需要来回切换勾选状态。

方式二：保持勾选，点【纯发送】

  • 适合平时带规则、偶尔追问时不想带规则。
  • 优点：不用改勾选状态，一键切换。
  • 纯发送时：
    • 不拼接规则
    • 聊天区不显示 [已附加 N 条规则]
    • 日志里记录“附加规则数：0”
    • 仍然走 history，仍然受上下文轮数影响

💡 纯聊天模式：不勾选任何规则时，发送行为跟普通聊天一样，只发输入框内容。

5.4 其他操作

操作方法

六、上下文与历史机制

这一章专门解释 history 到底存什么、有什么用、和规则勾选是什么关系。理解这一章，能帮你把「上下文轮数」设对。

6.1 history 里存什么

每轮 AI 回答完成后，程序会把两条消息成对存入 history：

角色内容
user你在输入框里敲的原文，不带规则
assistantAI 这一轮的完整回答

所以一轮 = 1 条 user + 1 条 assistant。

关键：history 里不含勾选规则。

规则只拼在每次实际发送的当前消息里，不进入 history。

原因：

  • 省 token，避免规则在历史里反复出现。
  • 避免历史里的旧规则稀释当前规则。
  • 让规则永远在最新位置，优先级最高。

6.2 每轮实际发送的结构

假设勾选了 1 条规则，当前输入是 ジョージは寝かしつけるのが大好き，发送给 API 的 messages 结构是：

[system]  固定人设

[历史 user 1]       ← 来自 history，原始输入，不带规则
[历史 assistant 1]  ← 来自 history，AI 回答

[历史 user 2]       ← 来自 history
[历史 assistant 2]

...

[当前 user]         ← 规则 + 【要处理的内容】 + 当前输入

规则只出现在最后一条当前 user 消息里。

6.3 两种典型用法

用法 A：每轮独立句子（推荐设轮数 0）

  • 你每轮只发一句新句子，勾选固定规则。
  • 不需要模型记住上一句。
  • 此时 history 对当前轮没有帮助，反而：
    • 浪费 token，增加费用
    • 可能把上一轮的错误格式带进来
    • 可能把上一句内容混进这一句
  • 建议把「上下文轮数」设为 0。

设 0 后，每轮只发：

[system]
[当前 user：规则 + 【要处理的内容】 + 当前句子]

最干净、最省、格式最稳。

用法 B：追问、指代、连续讨论（建议设轮数 2~8）

例如：

  • 第一轮：翻译：I love learning languages.
  • 第二轮：把上面那句话改成疑问句

第二轮必须知道第一轮内容，才需要 history。

这时把轮数设为 2~4 即可，追完可改回 0。

追问时如果不想带规则，点【纯发送】即可，不用取消勾选。

6.4 轮数达到上限会怎样

  • 工具栏显示如 8 / 8 轮，表示 history 里已攒了 8 轮。
  • 达到上限不会阻止发送，继续发送会显示 9 / 8、10 / 8。
  • 发送时始终只取最近 N 轮，旧的会自动被挤掉。
  • 显示超过上限只是提示，不影响功能。
  • 点【清空】会把 history 清空，轮数重置为 0。

💡 简单记：规则不占历史，历史只存原始对话。独立句子设 0，追问才开历史，追问不想带规则就点【纯发送】。

七、使用流程

7.1 基础使用

  1. 启动程序
  2. 点击【设置】，填入 API Key、Base URL、模型，点击「测试连接」确认可用后「保存」
  3. 在输入框输入要翻译或查询的内容，例如：
    Good morning, how are you?
  4. 按 Ctrl+Enter 或点击【发送】
  5. 查看 AI 回复（流式显示）

7.2 使用提示词（快捷填入）

  1. 点击【提示词】
  2. 选中一条 → 右键 →「使用」
  3. 内容自动填入输入框，可补充要翻译的文本
  4. 按 Ctrl+Enter 发送

7.3 使用规则勾选（推荐）

这是解决“多轮对话格式漂移”的推荐方式。

  1. 点击【提示词】
  2. 把完整提示词存成一条提示词（如果还没有）
  3. 单击该条左侧的 ☐，变成 ☑
  4. 关闭提示词窗口
  5. 在输入框里只写要处理的原文，例如：
    ジョージは寝かしつけるのが大好き
  6. 按 Ctrl+Enter 发送
  7. 程序自动拼接成：
    规则正文 + 【要处理的内容】 + 原文

为什么这样更稳？

规则每轮都出现在当前最新消息里，模型每轮都重新看到完整规则，不依赖它记住第一轮的内容，格式漂移大幅减少。

7.4 多轮对话与追问

  • 程序自动携带最近 N 轮历史（由「上下文轮数」决定）
  • 历史里保存的是你的原始输入，不含勾选规则
  • 可进行追问，例如：
    • 第一次：翻译：I love learning languages.
    • 第二次：把上面这句话改成疑问句
  • 追问时如果不想带规则，点【纯发送】即可，不用取消勾选
  • 若想开启全新话题，点击【清空】重置历史
  • 每轮独立句子的用法，建议把轮数设为 0，详见第六章

示例一：翻译与音标

10.2 用途

  • 确认每轮是否真的附加了规则
  • 确认规则正文是否完整
  • 排查 AI 格式漂移时，核对实际输入
  • 通过“附加规则数”区分带规则发送和纯发送

⚠️ 打包成 exe 后，日志写在 exe 同目录。若 exe 放在系统目录（如 C:\Program Files\），可能因权限不足无法写入。建议把 exe 放在桌面或 D 盘等用户目录。

十一、常见问题（FAQ）

Q1：点击发送提示"请先在【设置】里填写 API Key 并保存"？

A：说明尚未配置 API Key。请点击【设置】，填入有效的 API Key 后保存。

Q2：测试连接失败怎么办？

A：请依次检查：

  1. API Key 是否正确、是否过期
  2. Base URL 是否填写正确（注意结尾 /v1）
  3. 模型名称是否拼写正确
  4. 网络是否通畅（是否需代理）
  5. 账户余额是否充足

Q3：AI 回复很慢或没有反应？

  • 勾选设置中的「关闭思考（快速模式）」可加速
  • 减小「上下文轮数」可降低 token 消耗
  • 检查网络连接

Q4：修改设置后需要重启程序吗？

A：不需要。点击「保存」后立即生效。

Q5：如何开启新话题，避免历史干扰？

A：点击工具栏【清空】按钮，即可清空历史与显示内容。

Q6：提示词数据丢失了怎么办？

A：提示词保存在程序同目录的 prompts.json 中，可提前备份该文件。

Q7：窗口跑到屏幕外看不见了？

A：程序启动时会检测窗口位置，若超出屏幕范围会自动居中显示。也可手动编辑 config.json，将 win_x 和 win_y 改为 null。

Q8：提示"上下文轮数必须为正整数"？

A：请在设置中将「上下文轮数」填写为大于或等于 0 的整数（如 0 或 8）。

Q9：勾选了规则，但 AI 还是没按规则输出？

A：请依次排查：

  1. 打开 send_log.txt，确认最近一次发送内容里是否包含完整规则正文。
  2. 如果规则正文在，但 AI 没遵循，说明是模型遵循能力问题。可尝试：
    • 换更强的模型（如 deepseek-chat）
    • 精简规则，把最关键条款放最前面
    • 在规则末尾加一句“请严格按照以上格式输出，不要添加额外解释”
    • 点【清空】后重新开始，避免历史错误示例干扰
  3. 如果规则正文不在，说明勾选状态没生效，请回提示词窗口确认 ☑。

Q10：勾选多条规则会怎样？

A：会按列表顺序依次拼接，每条之间空一行，然后接 【要处理的内容】 和你的输入。建议只勾选必要规则，避免规则互相冲突或过长。

Q11：上下文轮数设为 0，勾选的规则还有效吗？

A：有效。规则是拼在当前这条消息里的，不依赖历史。上下文轮数只影响历史对话的携带，不影响规则附加。

Q12：我每轮都是独立句子，轮数设多少合适？

A：建议设 0。

原因：

  • 你不需要模型记住上一句。
  • 规则已经拼在当前消息里，不依赖历史。
  • 设 0 可以省 token、避免历史错误格式干扰、格式更稳。

如果你偶尔需要追问上一句，临时改成 2~4，追完再改回 0。

Q13：轮数达到 8/8 后还能继续发吗？

A：能。

8/8 只是显示 history 里攒了多少轮，不会阻止发送。继续发送会显示 9/8、10/8，但每次发送时始终只取最近 8 轮，更早的历史会被自动挤掉，不影响功能。

Q14：点【纯发送】和“取消勾选后点【发送】”有什么区别？

A：效果一样，都是不带规则发送。区别在操作方式：

  • 取消勾选 + 【发送】：需要来回切换勾选状态，适合整段时间都不带规则。
  • 【纯发送】：保持勾选不变，一键发送不带规则的消息，适合偶尔追问。

两者都会：

  • 不拼接规则
  • 聊天区不显示规则提示
  • 日志记录“附加规则数：0”
  • 仍然走 history，仍然受上下文轮数影响

Q15：支持哪些语言？

A：取决于所调用的模型能力。常见模型均支持中、英、日、韩、法、德、西等多语言。

Q16：程序可以打包成 exe 吗？

A：可以。使用 PyInstaller：

pyinstaller -F -w WINAPI.py

打包后 config.json、prompts.json、send_log.txt 会生成在 exe 同目录下。

十二、注意事项

  1. API 费用：程序本身免费，但调用 API 会产生费用，请注意账户余额与用量。
  2. 隐私保护：您发送的内容会传输至 API 服务商，请勿输入敏感信息。
  3. 网络依赖：本程序需联网才能使用 AI 功能。
  4. 配置安全：config.json 中明文保存 API Key，请勿分享该文件。
  5. 上下文轮数：
    • 每轮独立句子、规则固定：建议设 0。
    • 偶尔追问上一句：建议设 2~4。
    • 连续讨论一个话题：建议设 6~8。
    • 设置过大可能导致请求超时或费用上升。
  6. 规则长度：勾选的规则过长会占用大量 token，建议精简规则，只保留必要条款。
  7. 日志文件：send_log.txt 会记录你发送的内容，分享日志前请注意脱敏。
